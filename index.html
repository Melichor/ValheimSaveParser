Tools for your Valheim character: the achievements you are still missing, upgrades at the Forge of Potential, and how close your rare drops are. Everything runs in your browser.

Upgrade name finder

Every upgrade at the Forge of Potential is a dice roll, and the roll comes from the character that makes it: for a new character, from its name. Enter an item and the quality it starts at, and this finds names of new characters that give 8 upgrades in a row, the most one character can get. To go further, the relay planner below finds a chain of characters that pass the item along. It runs upgrade_oracle.py in your browser and needs no save file.

    Relay planner: more than 8 upgrades

    A chain of new characters can take an item as far as you want without breaking it: each one makes only the upgrades its own rolls get right, then hands the item to the next. Enter the item, its current quality and the quality you want.

      Before you create the characters

      • The case of the name is saved. The game keeps the name exactly as you type it, with its upper and lower case letters, even when the name box or the game shows it in capitals. FazI and fazi are different names with different rolls, so type it exactly as listed. (Only the file name is lowercase.)
      • Every upgrade must be made by the character listed for it. Each roll comes from the character making that upgrade, so an upgrade made by anyone else is a different roll that the list does not cover. With a relay plan, go in order: each character makes only its own listed upgrades, puts the item in a chest, and the next character takes it out and continues.
      • Use new characters. A name only works for the first item of this kind that character upgrades: once it has made an upgrade, the game stores a different roll for that item and level, so a second copy of the same item won't follow the list. The characters must never have upgraded this item type at the Forge of Potential before.
      • Unlock the item's recipe on each new character first. A new character does not know the item's base recipe yet. It needs to encounter the workbench (crafting station) the item is crafted at and register every item that is required to craft it. Bring the materials for its upgrades too.
      • Use an item that has not been upgraded at the Forge of Potential yet. If it was upgraded before the update, enter the level it has now. If it has already been upgraded on this update, this won't work for it. (This page is based on Valheim 1.0.20.)
      • Stop after the last upgrade listed. With a name from the finder that is the 8th, and a 9th attempt would break the item. In a relay plan, each character stops after its own levels.
      • Want your own "Crafted by:" name? The item shows the character that made its last upgrade, so in a relay plan that is the last character in the list. For a custom name, let a character with that name make the last upgrade. That roll comes from that character's name, not from the list, so check it first: in the Upgrade predictor tab, enter the item, the quality it has before that upgrade, and the custom name. If its first step works, the upgrade is safe. If it would break, stop a level or more earlier and check the custom name from there instead. This assumes a new character with that name, one that has not upgraded this item type at the Forge of Potential yet.
      • Each roll belongs to a level, not to the starting quality. A name found for, say, quality 3 to 11 also works for any part of that range, such as 6 to 11, because the rolls for levels 7 to 11 are the same ones. Starting below the quality you searched for is not covered: those lower levels were never checked.

      Upgrade predictor

      Drop a character file to see, for every upgradable item in its inventory, how many upgrades it can take at the Forge of Potential before it breaks. It runs upgrade_oracle.py in your browser and the file is never uploaded.

      Or predict a single item without a file, as a new character with the name you enter. A new character has no saved seeds, so every roll comes from the name.

      • The item must not have been upgraded at the Forge of Potential before.
      • The character must not have upgraded this item type at the Forge of Potential before, with any copy of it. If it has, drop its character file above instead: that uses the rolls stored in the file.

        How to read it

        • The roll for an upgrade comes from the character's name the first time it upgrades that item to that level, and from a stored seed in the file after that. The prediction uses whichever the file says applies, so it is exact for the next attempts of this character.
        • Each item is predicted as if it were the first of its kind you upgrade. With two copies of the same item, the second one continues from the seeds the first leaves behind, so its path differs.
        • An attempt that is not a success breaks the item, so each path ends with a break. You can stop before it: the path shows how far you would get.

        Upgrade cost

        What one character really pays to get an item to a quality at the Forge of Potential, without any name tricks. It crafts the item, upgrades it at its crafting station as far as that station goes, then tries the Forge. Every failed attempt breaks the item, so it crafts a new copy and starts again until one gets there. The rolls are that character's own, so the totals are exact for it, not an average. It runs upgrade_cost.py (with upgrade_oracle.py for the rolls) in your browser, and a character file you choose is never uploaded.

          How it counts
          
      
            
        
          • A name or a file. With a name, the character is new and every roll comes from the name. With a character file, its name and the rolls already stored in it are used, so it is exact for that character as it is now.
            • 
        
          • Crafting and station upgrades use the game's own amounts. From quality 4 on, a level counts as 4 steps plus half a step per level above 4, so the upgrade to 4 costs more than the one to 3.
            • 
        
          • Each copy goes to the highest quality its station can reach first. A station only gets one level per kind of extension, so some items stop below their max quality there (Deep North gear stops at 3).
            • 
        
          • Every Forge attempt costs one Idol, success or failure, and Idols are never refunded. The station materials are not used at the Forge.
            • 
        
          • A break refunds 35%, rounded up, of each refundable ingredient, counted from its craft amount and its per-level amount. The per-level amount is what the wiki lists as that ingredient's upgrade cost from quality 1 to 2. For an item that breaks at quality level (on its way to level + 1):
          
            refund = ⌈ 0.35 × ( craft + ⌊ ( ⌊2min(2, level − 2)⌋ + (max(4, level) − 4) / 2 ) × per_level ⌋ ) ⌉
            level is the item's quality when it broke, craft is the ingredient's craft amount, per_level its upgrade cost from quality 1 to 2. ⌈ ⌉ rounds up, ⌊ ⌋ rounds down.
            
          For example, a Fenris Hood (20 Fenris Hair to craft, 5 per level) breaking at quality 5 returns ⌈ 0.35 × (20 + ⌊4.5 × 5⌋) ⌉ = ⌈ 0.35 × 42 ⌉ = 15 Fenris Hair. Rounding up means single ingredients, like a trophy or a mould, come back every time (except the staffs' moulds, below).
            • 
        
          • Deep North gear and staffs are crafted as a cast. The finished item's own recipe is upgrade-only, so a new copy is crafted as a cast (using up its mould) and then cooked into the item in the Frost Foundry, which burns 5 Liquid Frost per cast. A copy therefore costs the cast's ingredients plus 5 Liquid Frost, and Liquid Frost is never refunded. Upgrades and break refunds use the finished item's upgrade recipe, which repeats the cast's ingredients.
            • 
        
          • Weapons made from another weapon count that weapon's whole recipe. The Frostfire and Thunderblood weapons are made from a Nord weapon, and the Ashlands variants (Wound, Storm and Root Rippers and Fangs, the Bleeding, Primal, Scourging and Thundering weapons, Bloodgeon, Storm Star, Klossen and others) from their base weapon. Each copy uses up a whole base weapon, so the tool lists what it takes to craft one instead: a Frostfire Sword shows the Nord Sword's Bloodgold, mould, Timberwood and Liquid Frost, not "1 Nord Sword". Crafting takes the first matching base weapon in your inventory, whatever its quality, so carry only the one you mean to use.
            • 
        
          • Never refunded: the Idols, Liquid Frost, a base weapon and everything crafted into it, the essence or gem of a variant (Frostfire and Thunderblood Essence, Bloodstone, Iolite, Jade), and anything the upgrade recipe leaves out (below). Only the remaining ingredients, like the metal, come back in part. The result lists what is never refunded for the chosen item.
            • 
        
          • The staffs never get their mould back. For Northern Vengeance, Spirit Caller, Lightning Strike and Echo Spike, the upgrade recipe leaves out the mould that the cast uses up, while the Deep North armor and weapons list theirs. So a broken staff refunds its other ingredients but never the mould. That looks like a game bug, and Nord Knucklechains have a similar one: their cast takes 2 Long Claws, but their upgrade recipe lists 10 Timberwood instead, so a break never returns claws but does return Timberwood the craft never used.
            • 
        
          • Keep space in your inventory for the refund. It goes straight into the inventory: each ingredient first tops up the stacks you already have, and whatever is left needs a free slot. If there is none, the game drops only a single item of it on the ground and the rest is lost; an ingredient that does not stack is lost completely. So keep a free slot for each refundable ingredient, or partial stacks with room for the refund. This tool assumes every refund arrives.

          Drop counters
          
    
          A creature drop with a chance of 30% or less (after stars) is not left to luck: it has a counter, saved in your character file, and the kill that runs the counter out drops the item. Drop a character file to see how many kills each rare drop is away, or look up any drop with a filter. It runs drop_counters.py in your browser and the file is never uploaded.
          
    
          
      
      
          
      
      
      
    
          
    
            
      
          • Part of a name is enough: trophy lists every trophy, greyd.troph the Greydwarf trophies, .coins every Coins drop. A single word matches the creature or the item, creature.item both, at every star level the creature can have (a boss has none). Only drops with a counter are listed: 30% or less after stars. Above that every kill is its own roll, so those are left out.
            • 
      
          • For one star level, put it in the middle (Greydwarf.1.TrophyGreydwarf), or at the end for every drop at that level (Wolf.2). Names are prefab names or display names (krigen), in any case; a full name matches just that one, and * stands for anything. Separate several filters with commas.
            • 
      
          • Without a filter you get every counter saved in the file; without a file, only the chances and the longest gaps.

          How the counters work
          
      
            
        
          • Stars double the chance: ×2 at one star, ×4 at two. A few drops ignore stars, such as Dvergr Soft Tissue and the Jotun Witch's moulds. A creature only gets stars from the spawners that make it, so some never have any: the bosses, and creatures like Lox, Deathsquitos, Serpents and Stone Golems. The page only lists the star levels a creature can have.
            • 
        
          • Above 30% it is luck. Every kill is an independent roll, with no counter.
            • 
        
          • At 30% or less there is a counter. With a chance p, the first drop comes within ⌊2 / p⌋ kills, and after each drop the next one comes after 1 to ⌊2 / p⌋ + 1 kills (the longest gap). Over many kills that is about the chance shown.
            • 
        
          • “In N kills” means the N-th kill from now drops it. Every kill of a creature that uses the counter counts it down.
            • 
        
          • Every star level has its own counter. A drop of 30% or less gets a separate counter, and a separate row here, for each star level of the creature: killing a 1★ Greydwarf does not move the counter of the 0★ ones. If the stars raise the chance above 30%, that star level no longer uses a counter and every kill is an independent roll. Creatures that drop the same item at the same chance do share a counter (the Shared with column): every kind of skeleton counts towards the same skeleton trophy.
            • 
        
          • The file is only as fresh as the last save. The game saves the character every 30 minutes, when you log out and when you quit. Kills since then are not in it yet.
            • 
        
          • In multiplayer, the game that owns the creature rolls the drop, with its player's counters. That is usually whoever reached the area first (the host, in a hosted game, when it is a tie). Near the world spawn on a dedicated server the server itself can own creatures. It rolls their drops with counters of its own, which it keeps in memory until it restarts but never saves to any character file.
            • 
        
          • Counters can carry over to the next character. The game keeps the counters in memory and never clears them until you quit. Loading a character, even just showing it on the character selection screen, puts its own counters on top. Every counter the character has stored keeps its own value, but one it has not stored yet (it never killed anything that uses it) is copied from a character loaded earlier in the same session, and saved with it from then on. A new character has nothing stored, so it copies every counter; an existing character copies only the ones it is missing.
