Upgrade time finder

Every upgrade at the Forge of Potential is a dice roll, and the roll comes from the character that makes it. Since Valheim 1.0.30, a new character's rolls come from the moment it was created, to the second, as the clock of the computer running the game shows it (its name no longer matters). Enter an item and the quality it starts at, and this finds creation times that give up to 8 upgrades in a row, the most one character can get. To go further, the relay planner below finds a chain of characters that pass the item along. It runs upgrade_oracle.py in your browser and needs no save file.

    Relay planner: more upgrades

    A chain of new characters can take an item as far as you want without breaking it: each one makes only the upgrades its own rolls get right, then hands the item to the next. Enter the item, its current quality and the quality you want. Fewer levels per character means more characters, but creation times only about a minute apart.

      Before you create the characters

      • DON'T GO PAST 10K TOTAL DAMAGE. When an item's damage of all types added together comes to more than 10,000, the game marks it as a cheated item the next time it loads, and the mark stays even if the item is later brought back below that (a Club, for example, reaches it at quality 1,666).
      • The creation second is what counts. The game takes the time when you press Done after typing the new character's name (pressing New before it is safe: that only opens the screen), and only the whole second is kept. The Creation timer beeps you onto it. Have the clock of the computer running the game in view (with seconds) and press it during the listed second. You can wait for that time, or set the computer's clock to just before it. Set the Time zone at the top of the page to the zone of that computer (it starts as yours): the times are its local times, and the finder leaves out the times its clock skips when summer time starts. Otherwise the zone changes nothing: the game reads the time back exactly as the clock showed it.
      • Check before you upgrade. Load the new character once and quit, then drop its .fch file in the Upgrade predictor tab: it shows the creation time the game saved and the path that time gives. If you missed the second, delete the character and try again.
      • The name doesn't matter. Name the characters whatever you like. The item shows the character that made its last upgrade as "Crafted by:", so in a relay plan the last character's name ends up on the item.
      • Every upgrade must be made by the character listed for it. Each roll comes from the character making that upgrade, so an upgrade made by anyone else is a different roll that the list does not cover. With a relay plan, go in order: each character makes only its own listed upgrades, puts the item in a chest, and the next character takes it out and continues.
      • Use new characters. A creation time only works for the first item of this kind that character upgrades: once it has made an upgrade, the game stores a different roll for that item and level, so a second copy of the same item won't follow the list. The characters must never have upgraded this item type at the Forge of Potential before.
      • Unlock the item's recipe on each new character first. A new character does not know the item's base recipe yet. It needs to encounter the workbench (crafting station) the item is crafted at and register every item that is required to craft it. Bring the materials for its upgrades too.
      • Use an item that has not been upgraded at the Forge of Potential yet. If it was upgraded before, enter the level it has now. (This page is based on Valheim 1.0.30.)
      • Stop after the last upgrade listed. With a time from the finder, the next attempt would break the item. In a relay plan, each character stops after its own levels.
      • Each roll belongs to a level, not to the starting quality. A time found for, say, quality 3 to 11 also works for any part of that range, such as 6 to 11, because the rolls for levels 7 to 11 are the same ones. Starting below the quality you searched for is not covered: those lower levels were never checked.

      Upgrade predictor

      Drop a character file to see, for every upgradable item in its inventory, how many upgrades it can take at the Forge of Potential before it breaks. It runs upgrade_oracle.py in your browser and the file is never uploaded.

      Or predict a single item without a file, for a new character created at the date and time you enter, as the game computer's clock showed it. A new character has no saved seeds, so every roll comes from its creation time. In the game, the stats page of the compendium (and the console's stats command) shows it as Created:.

      • The item must not have been upgraded at the Forge of Potential before.
      • The character must not have upgraded this item type at the Forge of Potential before, with any copy of it. If it has, drop its character file above instead: that uses the rolls stored in the file.

        How to read it

        • The roll for an upgrade comes from the character's creation time the first time it upgrades that item to that level, and from a stored seed in the file after that. The prediction uses whichever the file says applies, so it is exact for the next attempts of this character.
        • The time zone matters for a file. The file stores the creation time in UTC, and the game turns it into local time with the time zone of the computer it runs on. The Time zone at the top of the page sets that zone; it starts as yours (). Check that the creation time shown matches the game's Created:; if not, the zone is wrong.
        • Each item is predicted as if it were the first of its kind you upgrade. With two copies of the same item, the second one continues from the seeds the first leaves behind, so its path differs.
        • An attempt that is not a success breaks the item, so each path ends with a break. You can stop before it: the path shows how far you would get.

        Upgrade cost

        What one character really pays to get an item to a quality at the Forge of Potential, without any creation-time tricks. It crafts the item, upgrades it at its crafting station as far as that station goes, then tries the Forge. Every failed attempt breaks the item, so it crafts a new copy and starts again until one gets there. The rolls are that character's own, so the totals are exact for it, not an average. It runs upgrade_cost.py (with upgrade_oracle.py for the rolls) in your browser, and a character file you choose is never uploaded.

          How it counts
          
      
            
        
          • A creation time or a file. With a creation time, the character is new and every roll comes from that time (the game's Created:). With a character file, its creation time (read in the Time zone chosen at the top of the page, which starts as yours, ) and the rolls already stored in it are used, so it is exact for that character as it is now.
            • 
        
          • Crafting and station upgrades use the game's own amounts. From quality 4 on, a level counts as 4 steps plus half a step per level above 4, so the upgrade to 4 costs more than the one to 3.
            • 
        
          • Each copy goes to the highest quality its station can reach first. A station only gets one level per kind of extension, so some items stop below their max quality there (Deep North gear stops at 3).
            • 
        
          • Every Forge attempt costs one Idol, success or failure, and Idols are never refunded. The station materials are not used at the Forge.
            • 
        
          • A break refunds 65% of everything the item took so far, rounded to the nearest whole number: of each refundable ingredient, its craft amount plus what every upgrade up to the item's quality took. The per-level amount is what the wiki lists as that ingredient's upgrade cost from quality 1 to 2. For an item that breaks at quality level (on its way to level + 1):
          
            refund = round( 0.65 × ( craft + Σq = 2 … level ⌊ step(q) × per_level ⌋ ) ),  step(q) = q − 1 below quality 4, 4 + (q − 4) / 2 from 4 on
            level is the item's quality when it broke, craft is the ingredient's craft amount, per_level its upgrade cost from quality 1 to 2. ⌊ ⌋ rounds down; round() rounds to the nearest whole number, an exact half to the even one.
            
          For example, a Fenris Hood (20 Fenris Hair to craft, 5 per level) breaking at quality 5 returns round(0.65 × (20 + 5 + 10 + 20 + ⌊4.5 × 5⌋)) = round(0.65 × 77) = 50 Fenris Hair. Single ingredients, like a trophy or a mould, come back every time (0.65 rounds to 1), except the staffs' moulds (below). Before Valheim 1.0.30 a break refunded only 35% of the craft amount plus the last level's amount.
            • 
        
          • Deep North gear and staffs are crafted as a cast. The finished item's own recipe is upgrade-only, so a new copy is crafted as a cast (using up its mould) and then cooked into the item in the Frost Foundry, which burns 5 Liquid Frost per cast. A copy therefore costs the cast's ingredients plus 5 Liquid Frost, and Liquid Frost is never refunded. Upgrades and break refunds use the finished item's upgrade recipe, which repeats the cast's ingredients.
            • 
        
          • Weapons made from another weapon count that weapon's whole recipe. The Frostfire and Thunderblood weapons are made from a Nord weapon, and the Ashlands variants (Wound, Storm and Root Rippers and Fangs, the Bleeding, Primal, Scourging and Thundering weapons, Bloodgeon, Storm Star, Klossen and others) from their base weapon. Each copy uses up a whole base weapon, so the tool lists what it takes to craft one instead: a Frostfire Sword shows the Nord Sword's Bloodgold, mould, Timberwood and Liquid Frost, not "1 Nord Sword". Crafting takes the first matching base weapon in your inventory, whatever its quality, so carry only the one you mean to use.
            • 
        
          • Never refunded: the Idols, Liquid Frost, a base weapon and everything crafted into it, the essence or gem of a variant (Frostfire and Thunderblood Essence, Bloodstone, Iolite, Jade), and anything the upgrade recipe leaves out (below). Only the remaining ingredients, like the metal, come back in part. The result lists what is never refunded for the chosen item.
            • 
        
          • The staffs never get their mould back. For Northern Vengeance, Spirit Caller, Lightning Strike and Echo Spike, the upgrade recipe leaves out the mould that the cast uses up, while the Deep North armor and weapons list theirs. So a broken staff refunds its other ingredients but never the mould. That looks like a game bug, and Nord Knucklechains have a similar one: their cast takes 2 Long Claws, but their upgrade recipe lists 10 Timberwood instead, so a break never returns claws but does return Timberwood the craft never used.
            • 
        
          • Keep space in your inventory for the refund. It goes straight into the inventory: each ingredient first tops up the stacks you already have, and whatever is left needs a free slot. If there is none, the game drops only a single item of it on the ground and the rest is lost; an ingredient that does not stack is lost completely. So keep a free slot for each refundable ingredient, or partial stacks with room for the refund. This tool assumes every refund arrives.

            How to use it
            
      
              
        
            • The press that counts is Done. In the character selection, pressing New is safe: it only opens the new character screen, and the time is not taken yet. Take your time there: type the name (at least 3 letters, or Done stays greyed out) and pick the looks. The creation time is taken the moment you press Done, so that is the press to put on the fifth beep. (If the game then says the cloud storage is full and you choose to save locally, the time is taken when you confirm that instead.)
              • 
        
            • The fifth beep marks the start of the second. The game keeps only the whole second in which you press Done, so anything from the fifth beep until just before the next second counts. Pressing right after you hear it lands a few hundred milliseconds in, which is safe.
              • 
        
            • Shift moves all five beeps, in milliseconds: +300 makes them 0.3 s later, -200 0.2 s earlier. If you tend to press on the beat or a little ahead of it, a shift of about +300 to +500 puts your press safely inside the second. It is remembered in this browser.
              • 
        
            • Calibrate with the test. Test in 5 s plays the same five beeps on the next whole second five seconds away; compare the loud beep with the clock above, or with a clock showing seconds on the game's computer, and adjust the shift until they agree. The beeps already allow for the sound output delay the browser reports; Bluetooth headphones can add more.
              • 
        
            • Keep this tab open. The beeps are scheduled with the audio clock about 15 seconds ahead, so they stay on time even if the tab is in the background then, but the browser must not be closed or asleep. Starting the timer also unlocks sound, which browsers only allow after a click.
              • 
        
            • Check afterwards. Load the new character once, quit, and drop its file under Check the result: it shows the creation time the game saved, how many seconds off it is and what shift to try. The Upgrade predictor then shows the upgrade path that time gives.

            Drop counters
            
    
            A creature drop with a chance of 30% or less (after stars) is not left to luck: it has a counter, saved in your character file, and the kill that runs the counter out drops the item. Drop a character file to see how many kills each rare drop is away, or look up any drop with a filter. It runs drop_counters.py in your browser and the file is never uploaded.
            
    
            
      
      
            
      
      
      
    
            
    
              
      
            • Part of a name is enough: trophy lists every trophy, greyd.troph the Greydwarf trophies, .coins every Coins drop. A single word matches the creature or the item, creature.item both, at every star level the creature can have (a boss has none). Only drops with a counter are listed: 30% or less after stars. Above that every kill is its own roll, so those are left out.
              • 
      
            • For one star level, put it in the middle (Greydwarf.1.TrophyGreydwarf), or at the end for every drop at that level (Wolf.2). Names are prefab names or display names (krigen), in any case; a full name matches just that one, and * stands for anything. Separate several filters with commas.
              • 
      
            • Without a filter you get every counter saved in the file; without a file, only the chances and the longest gaps.

            How the counters work
            
      
              
        
            • Stars double the chance: ×2 at one star, ×4 at two. A few drops ignore stars, such as Dvergr Soft Tissue and the Jotun Witch's moulds. A creature only gets stars from the spawners that make it, so some never have any: the bosses, and creatures like Lox, Deathsquitos, Serpents and Stone Golems. The page only lists the star levels a creature can have.
              • 
        
            • Above 30% it is luck. Every kill is an independent roll, with no counter.
              • 
        
            • At 30% or less there is a counter. With a chance p, the first drop comes within ⌊2 / p⌋ kills, and after each drop the next one comes after 1 to ⌊2 / p⌋ + 1 kills (the longest gap). Over many kills that is about the chance shown.
              • 
        
            • “In N kills” means the N-th kill from now drops it. Every kill of a creature that uses the counter counts it down.
              • 
        
            • A counter belongs to the item and its chance after stars. So a drop that stars make more likely gets a separate counter for each star level of the creature, and a separate row here: killing a 1★ Greydwarf does not move the counter of the 0★ ones. If the stars raise the chance above 30%, that star level no longer uses a counter (every kill is an independent roll) and is not listed. A drop whose chance stays the same at every star level, like the Jotun Witch's moulds, has one counter for all of them: any Hexen kill counts it down, whatever its stars, and its rows list the other star levels under Shared with. Creatures that drop the same item at the same chance share a counter too: every kind of skeleton counts towards the same skeleton trophy.
              • 
        
            • The file is only as fresh as the last save. The game saves the character every 30 minutes, when you log out and when you quit. Kills since then are not in it yet.
              • 
        
            • In multiplayer, the game that owns the creature rolls the drop, with its player's counters. That is usually whoever reached the area first (the host, in a hosted game, when it is a tie). Near the world spawn on a dedicated server the server itself can own creatures. It rolls their drops with counters of its own, which it keeps in memory until it restarts but never saves to any character file.
              • 
        
            • Counters can carry over to the next character. The game keeps the counters in memory and never clears them until you quit. Loading a character, even just showing it on the character selection screen, puts its own counters on top. Every counter the character has stored keeps its own value, but one it has not stored yet (it never killed anything that uses it) is copied from a character loaded earlier in the same session, and saved with it from then on. A new character has nothing stored, so it copies every counter; an existing character copies only the ones it is missing.
